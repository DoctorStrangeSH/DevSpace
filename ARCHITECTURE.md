# DevSpace — устройство и безопасность

## Два независимых слоя

- **Публичное портфолио** — разделы `#featured`, `#about`, контакты. Доступны посетителям без входа, данные берутся из проверенных ссылок на репозитории.
- **Истории проектов** — маршруты `#project/<slug>`, данные и рендер в `js/portfolio.js`; не требуют сборщика, не зависят от Firebase и открываются по прямым ссылкам. Иллюстрации сейчас концептуальные, а не игровые скриншоты.
- **Vercel-проекты** — вручную проверенная витрина четырёх проектов в `#web-projects`. Статус сборки `READY` не означает публичный доступ; текущие проекты используют Vercel SSO Protection, поэтому на карточках есть явное предупреждение. Приватные исходники не раскрываются ссылками.
- **GitHub metadata** — `js/github-metadata.js` запрашивает только шесть явно разрешённых публичных репозиториев. Поля `private` и `full_name` проверяются перед показом, нет токенов, кеш сессии живёт 30 минут. При сетевой ошибке сведения не выводятся, а основной сайт продолжает работать. Это сведения о последней отправке кода (`pushed_at`), а не обещание актуального статуса разработки.
- **Мастерская** — существующий трекер проектов, задач, заметок и достижений. Локальные правки хранятся в браузере (через `StorageService`). В интерфейсе доступны экспорт и импорт резервных копий.

## Известные ограничения

В старой версии `AuthService` сравнивает введённую строку с ключом внутри публичного JavaScript. **Это переключатель интерфейса, а не безопасная авторизация.** Его нельзя использовать как доказательство прав владельца для API или Firestore Security Rules. Старый ключ считается раскрытым — смена только в клиентском коде ничего не защитит.

Firebase используется для чтения опубликованных данных. Запись отключена в `FirebaseService` и `SyncModule`, чтобы не выполнять опасные операции из публичного клиента. **Обязательно отдельно проверить правила Firestore в консоли Firebase:** само отключение кнопок/методов сайта не запрещает прямые запросы к базе.

Для полноценного безопасного редактирования с разных устройств следующий этап — Firebase Authentication (пользователь-владелец с UID) и Firestore Rules, разрешающие запись только проверенному UID. Перед включением облачных записей нужны резервная копия текущей коллекции и тест правил в эмуляторе.

## Публикация

GitHub Pages публикует корень ветки `main`. Пути в `sw.js` относительные, потому что проект живёт по адресу `/DevSpace/`, а не в корне домена. При изменении статических ресурсов повышайте `CACHE_VERSION`.
