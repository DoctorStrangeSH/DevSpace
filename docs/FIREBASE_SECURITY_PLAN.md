# DevSpace — безопасная облачная синхронизация

Статус на 16.11.2026: пользователь подтвердил публикацию правил и успешный приватный предпросмотр: **10 новых локальных проектов, 0 совпадений, 0 пропусков, 0 облачных**. Это подтверждает чтение своей коллекции через его сессию, но не проверяет независимо все ограничения правил. Облачная запись по-прежнему отключена.

## Срочный результат аудита

Исходное правило `allow read, write: if true` делало все документы публичными для чтения, изменения и удаления (оценка 1/5, критический риск). Пользователь сообщил, что заменил его на временное правило `allow read, write: if false`. После восстановления безопасных правил проверьте целостность данных: блокировка не отменяет возможные изменения, сделанные ранее.

`firestore.rules` — правила **только для чтения приватных проектов**, опубликованные пользователем согласно его сообщению. Они разрешают владельцу читать `/users/{uid}/projects`, но запрещают **любые записи**, включая проекты, историю здоровья и настройки. Следующие изменения правил записи необходимо проверить отдельно в эмуляторе и согласовать перед публикацией.

Формат будущей записи `users/{uid}/projects/{projectId}`: `{ id: projectId, schemaVersion: 1, payload: JSON.stringify(project), updatedAt: serverTimestamp() }`. Будущая схема ограничит `payload` 200 000 символами, а сейчас все записи заблокированы. `payload` **не считается доверенным HTML** при чтении. Единственный источник прав на чтение — Firebase Auth UID в пути. Клиентская запись по-прежнему отключена и не включается публикацией этих файлов в GitHub.

## Перенос локальных проектов — подготовительный этап

`SyncModule._planPrivateMigration(localProjects, remoteProjects)` строит **только предварительный план**. Он не вызывает Firebase и не изменяет исходные массивы. Для новых допустимых ID выдаётся отдельная копия проекта; совпадающие ID отмечаются конфликтами, а повторяющиеся и некорректные записи пропускаются. Размер JSON-поля ограничен 200 000 символами. Текущая функция `uploadToCloud()` по-прежнему возвращает `false`.

Подготовлен `FirebaseService.createPrivateProjectIfAbsent(project, expectedUid)` — транзакционная запись **ровно одного** проекта только при отсутствии документа с этим ID. Перед записью проверяются формат данных, Google UID и отсутствие проекта; после транзакции результат сверяется повторным чтением. При смене аккаунта или конфликте возвращается `false`, существующий документ не перезаписывается. Метод защищён отдельным **отключённым** флагом `_privateProjectCreatesEnabled: false`; в текущем сайте ни одна кнопка его не вызывает. Он проверяется тестами с подставной базой, а не на рабочем Firestore. Для включения понадобятся отдельные правила разрешения только `create` и их эмуляторная проверка.

Черновик следующего этапа — **`firestore.create-only.rules`**, не подключённый к `firebase.json`. Он разрешает только авторизованному владельцу создать новый проект с точным набором полей, корректным ID, ограниченным JSON-полем и серверной датой; чтение ограничено тем же UID, изменения и удаления запрещены. Есть отдельные тесты `tests/firestore.create-only.rules.test.cjs` на чужие аккаунты, публичный доступ, изменение документа и подмену полей. Это **не текущие опубликованные правила** и не команда публиковать их сейчас. Перед использованием требуется успешный прогон Firestore Emulator, уточнение edition базы и согласование перехода с владельцем.

Перед реальным переносом необходимы правила записи для `users/{uid}/projects/{id}` с полной схемой и тестами в Firestore Emulator, явный выбор пользователя для конфликтов, локальная резервная копия и проверка результата чтением после записи.

`FirebaseService.getPrivateProjectPreview()` — отдельная ограниченная (100 документов) операция чтения `users/{uid}/projects`, где UID берётся только из активной Firebase Auth-сессии. Она ничего не сохраняет, не заменяет локальные проекты и отбрасывает результат, если аккаунт сменился во время запроса. До публикации и проверки соответствующих правил она может возвращать `null` из-за отказа Firestore.

Предварительное чтение теперь принимает **только** конверты версии 1 с допустимым ID и JSON-объектом, чей `id` совпадает с ID документа. При повреждённой записи предварительный просмотр отменяется целиком: она не исправляется автоматически и не импортируется в локальное хранилище. `FirebaseService._preparePrivateProjectEnvelope(project)` готовит `{id, schemaVersion, payload}` без `updatedAt` и без сетевого запроса — для будущей операции записи потребуется серверная метка времени и отдельное подтверждение пользователя.

В интерфейсе версии 3.62.5 есть кнопки **«Проверить перенос в облако»** и **«Скачать резервную копию»**. После Google-входа первая выполняет только чтение и показывает количество новых проектов, совпадений и пропусков. Вторая доступна и без Google-входа и сохраняет локальный JSON-бэкап через существующий механизм экспорта. При недоступных правилах, некорректном документе или достижении лимита в 100 записей план не строится, чтобы случайно не принять неполный список за полный. Никакие локальные данные и облачные документы при просмотре не меняются. Планировщик использует те же 200 000 символов на JSON-поле, что и прототип правил.

При выходе из Google или смене UID активный предпросмотр отменяется с помощью номера запроса: результат старой сессии не показывается новому пользователю, даже если сетевой запрос завершится позже. Ошибки чтения оставляют локальное состояние неизменным. Эти сценарии проверяются автоматическими тестами без подключения к рабочей базе.

Начиная с версии 3.62.5 предпросмотр различает ошибки `permission-denied` (правила доступа), `unauthenticated` (нет сессии), `unavailable` (сеть/сервис), `deadline-exceeded` (тайм-аут), некорректные документы и превышение ограничения в 100 проектов. Пользователю показывается короткая инструкция без сырого текста исключений, токенов и данных проектов; после успешного чтения прежняя ошибка сбрасывается.

## Автоматическая проверка Security Rules

Добавлен отдельный CI job `Firestore rules emulator`, использующий исключительно тестовый проект `demo-devspace-rules`. Тесты в `tests/firestore.rules.test.cjs` проверяют чтение своих проектов, запрет чтения чужих, запрет старых коллекций и **любых записей** в текущем этапе. Локально их можно запустить после установки `firebase-tools`, `@firebase/rules-unit-testing` и `firebase` командой:

```sh
npx firebase emulators:exec --only firestore --project demo-devspace-rules 'node --test tests/firestore.rules.test.cjs'
```

Это проверка прототипа, **не деплой в живой Firebase**. До успешного CI не считать правила валидированными.

## Будущая структура

Новые приватные данные размещаются под `users/{uid}` — никогда не в текущей общей коллекции `projects` с `userId: 'owner'`.

| Путь | Содержимое | Доступ |
|---|---|---|
| `users/{uid}/healthHistory/{date}` | Оценки за день | Пока полностью запрещён |
| `users/{uid}/settings/main` | Настройки пользователя | Пока полностью запрещён |
| `users/{uid}/projects/{id}` | Проекты владельца | Чтение только своего UID; запись запрещена |

Ни email, ни включённый локальный редактор, ни `userId: 'owner'` не являются доказательством прав доступа.

## Источник прототипа правил

Единственный актуальный прототип — [`firestore.rules`](../firestore.rules). Более ранние сокращённые примеры с `allow write: if isSelf(uid)` **не использовать**: они не проверяют структуру документов. Перед будущим деплоем обязательны успешные эмуляторные тесты, сверка с действующими правилами и отдельное согласование.

## Проверки перед переключением

- Анонимный клиент не может читать или писать `/users/{uid}/...`.
- Пользователь A не может читать или изменять данные пользователя B.
- Пользователь A может работать только со своим UID.
- Ошибки сети не удаляют локальные проекты; конфликты решаются по отдельным записям, а не заменой всего массива.
- Никакой пароль, service account key и Firebase Admin SDK не попадают в GitHub Pages.
- Старая публичная витрина проектов сохраняет необходимое чтение, но не получает анонимную запись.

Официальные справочники: [Security Rules](https://firebase.google.com/docs/firestore/security/rules-conditions), [поля документов](https://firebase.google.com/docs/firestore/security/rules-fields).
