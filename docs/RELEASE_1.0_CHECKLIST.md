## Ручная приёмка перед публикацией

Проводить на реальном браузере и хотя бы одном телефоне. Автоматические тесты не заменяют эти проверки.

### Основные сценарии

- [ ] Открыть сайт в чистом профиле браузера.
- [ ] Проверить публичное портфолио, прямые ссылки на истории проектов и галереи.
- [ ] Перезагрузить страницу и убедиться, что навигация и локальные данные не потерялись.
- [ ] Создать тестовый проект, задачу и заметку; перезагрузить страницу и проверить сохранность.
- [ ] Экспортировать резервную копию, импортировать её в отдельный тестовый профиль и сверить данные.
- [ ] Импортировать некорректный файл и убедиться, что он не приводит к тихой потере текущих данных.
- [ ] Проверить поведение при заполненном хранилище: приложение должно показать ошибку, а не сообщить об успешном сохранении.

### PWA и офлайн

- [ ] Установить PWA после успешной онлайн-загрузки.
- [ ] Открыть приложение после отключения сети.
- [ ] Проверить основные локальные экраны и статические ресурсы без сети.
- [ ] Обновить приложение с предыдущей версии и убедиться, что новая версия активируется после успешного precache.
- [ ] Убедиться, что при неудачной загрузке обязательного ресурса предыдущая рабочая версия остаётся доступной.
- [ ] Проверить открытие установленного приложения и его ярлыков.

## Облачный перенос — отдельное ограничение приёмки

- [x] Автоматическая облачная запись/синхронизация через `SyncModule` отключена.
- [x] Локальный переключатель «Правки» явно не является входом или серверной авторизацией.
- [x] Реализован отдельный ручной перенос через Google Identity: резервная копия, предпросмотр, повторная проверка UID/конфликтов и create-only запись отсутствующих проектов.
- [ ] Проверить production Firestore Rules и домены Firebase Authentication.
- [ ] Сверить правила в Firebase Console с правилами репозитория.
- [ ] Выполнить отдельную контролируемую запись одного тестового проекта и подтвердить её чтением.

**Важно:** клиентский флаг `_privateProjectCreatesEnabled` включён, но `firebase.json` указывает на `firestore.rules`, где клиентские записи запрещены. `firestore.create-only.rules` — прототип и не подключён к деплою. Поэтому CI подтверждает только активные read-only правила; он не подтверждает возможность ручной записи в production. До отдельной проверки считать ручной облачный перенос неподтверждённым. Это не блокирует локальную работу и локальный JSON backup, но должно быть честно описано в интерфейсе и релизных материалах.

## Границы текущей архитектуры

- Локальный режим редактирования хранит изменения в браузере через `StorageService`.
- Запись в Firebase отключена в публичном клиенте и `SyncModule`; текущий релиз не обещает облачную синхронизацию между устройствами.
- Эмулятор проверяет правила из репозитория, но не доказывает, что именно эти правила опубликованы в Firebase Console. Перед включением облачных записей требуется отдельно проверить production Firestore Rules, настроить Firebase Authentication с UID владельца и сделать резервную копию коллекции.
- Локальный режим редактирования не является серверной авторизацией и не должен использоваться как подтверждение прав для API или Firestore.

## Критерии готовности 1.0

Релиз можно объявлять готовым, когда:

1. Все обязательные CI-проверки зелёные на последнем коммите `main`.
2. Все ручные пункты выше проверены на реальных устройствах.
3. Не осталось известных критических ошибок, потери данных или ложных сообщений об успешном сохранении.
4. Резервная копия экспортируется и восстанавливается в отдельном профиле.
5. Описание архитектурных ограничений и способ хранения данных доступно пользователю.

Если ручной пункт не проверен, он остаётся открытым — его нельзя считать пройденным только на основании CI.
