## Результат инвентаризации

GitHub API вернул 80 удалённых веток: `main` и 79 дополнительных веток.

Среди дополнительных веток есть несколько типов:

- старые ветки уже объединённых PR;
- заменённые ветки;
- feature/fix ветки, которые могут содержать незавершённую работу;
- старые ветки документации и тестирования.

Сам факт отсутствия открытого PR **не доказывает**, что ветка безопасна для удаления. Перед удалением нужно проверить, что все её коммиты уже входят в `main`, либо что ветка явно заменена другой реализацией. Поэтому массовое удаление по имени или возрасту не выполнялось.

## Безопасная локальная проверка

Сначала обновите сведения с GitHub:

```bash
git fetch --prune origin
```

Покажите только удалённые ветки, чьи коммиты уже достижимы из `origin/main`:

**PowerShell**
```powershell
git branch -r --merged origin/main |
  Where-Object { $_ -notmatch 'origin/HEAD|origin/main' } |
  ForEach-Object { $_.Trim() }
```

**Bash**
```bash
git branch -r --merged origin/main |
  grep -vE 'origin/HEAD|origin/main'
```

Это список кандидатов на удаление, а не команда удаления. Перед удалением каждой ветки проверьте, что она не используется в текущей работе и не является единственной копией незавершённой реализации.

Удалять подтверждённую ветку можно отдельно:

```bash
git push origin --delete <branch-name>
```

Если ветка не входит в `origin/main`, сначала сравните её с `main` и найдите связанные PR/коммиты. Не используйте массовый `git push --delete` для непроверенного списка.

## Правила на будущее

1. Одна задача — одна короткоживущая ветка.
2. После merge PR удалённая feature/fix/docs ветка удаляется, если в ней нет отдельной незавершённой работы.
3. Не создавать несколько веток для последовательных правок одной и той же задачи.
4. Документационные и тестовые ветки также удалять после merge.
5. `main` — единственная ветка публикации GitHub Pages.
6. Перед любой массовой очисткой повторно получить актуальный список веток и проверить их ancestry.
